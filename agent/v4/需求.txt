# V4 需求：RAG 模式改造

## 背景

当前 RAG 流程是**固定执行**的：每次请求先查知识库，结果强制注入 HumanMessage，
再传给 Agent。模型没有选择权——不管问题是否需要知识库，都会收到知识库内容。

## 目标

把 RAG 从**固定流程**改为**可选工具**，让模型自己判断是否需要查知识库。

## 需求拆解

### 1. 清理死代码

`prompts.py` 中 `build_system_prompt(knowledge_text)` 的 `knowledge_text` 参数
从未被调用过（system_prompt 编译时写死，无法运行时注入），应清理掉。

### 2. RAG 作为工具

当前流程：
  _knowledge_search(question) → 注入 HumanMessage → Agent.run()

目标流程：
  Agent.run() → 模型判断 → 调用 knowledge_search 工具 → Agent 继续

具体做法：
  - 把 `knowledge_search` 封装成 LangChain Tool
  - 注册到 `build_tools()` 的工具列表
  - 系统提示词说明何时应查询内部知识库
  - Agent 自己决定：先查知识库 / 直接回答 / 联网搜索

### 3. 内部知识库工具行为

  - 工具名：`query_knowledge_base`
  - 入参：搜索关键词（模型自行生成）
  - 返回：知识库匹配片段（文本）
  - 如果知识库不可用（后端挂了 / 未配置），工具返回提示信息而非报错

### 4. 系统提示词调整

  补充知识库工具的调用指引：
  - 当用户问题涉及内部资料、项目文档、群历史时，先调用 `query_knowledge_base`
  - 知识库结果不足时，可继续调用 `web_search`
  - 日常闲聊、常识问答无需调用

### 5. 提示词引用说明更新

  当前提示词中「内部知识库优先」的描述是针对"已经被注入到 HumanMessage 里"
  的场景写的，需要更新为"模型自己调用工具查询"的场景。

## 涉及文件

| 文件 | 改动 |
|------|------|
| `prompts.py` | 清理 `build_system_prompt` 死参数，更新系统提示词，去掉「内部知识库优先」旧描述 |
| `tools.py` | 新增 `query_knowledge_base` 工具 |
| `agent.py` | `_build_input` 去掉 `knowledge_text` 注入逻辑，`_knowledge_search` 删除 |
| `knowledge.py` | 暴露 `search` 作为工具可调用接口 |

## 不做的事

- 不做用户画像
- 不改变系统提示词的编译方式（依旧单例编译，不改每次请求重新编译）
- knowledge_text 继续走 HumanMessage 注入的方案（改工具化后不再需要）
